<b>Learning by building:</b> AI tools and techniques change from month to month, so I test them on real software instead of just reading about them. I use Claude Code and Cursor, including Cursor's cloud agents. I compare planning modes, prompting styles and spec-driven frameworks such as GSD. I keep what works, drop what does not and write down why.

<b>Testing AI agents:</b> I built Verdant, a private Tessl workspace with two skill packages. They teach agents when to use Git worktrees and when to use stacked pull requests. Verdant has nine levelled eval scenarios, with weighted rubrics, blocking failures and adversarial cases, run against a pinned, Bash-validated fixture repository. I planned it with GSD in 5 phases, 21 plans and 56 tasks. Contract tests, path-scoped CI and a verified publish dry-run back it.

<b>Parallel agents, human review:</b> I ran background agents in parallel Git worktrees to build a 19-story redesign of a guitar-lesson player (SolidJS, Bun, Storybook). I gave the hardest stories to a stronger model and the rest to a faster one. I reviewed the work and merged it as one pull request. The project reached 290 tracked issues and 199 commits in under four weeks.

<b>Specs and quality gates:</b> Every feature starts with a written spec and user stories kept in Beads, an issue tracker built for agents. The agents work behind a pre-commit hook that mirrors CI, with behavior-driven tests, Storybook and screenshot-based visual checks. Hexkit, my contract-driven API generator, was also spec-first: an RFC and a PRD before code, then a 90% coverage gate.

<b>Better process:</b> I change my workflow when the results tell me to. Review work and token costs grew, so I moved from stacked pull requests to one epic branch. I replaced manual visual checks with screenshot comparison. I turned a long `AGENTS.md` into reusable skills. I packaged the lessons as eight repository skills and an open-source starter template, [bun-agentic-starter](https://github.com/williamrjribeiro/bun-agentic-starter).
